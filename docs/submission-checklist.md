# Submission Checklist

Submit on **Vultr Community** before your region's close time. Late submissions are not accepted. Submit early, since a moderator reviews each project before it goes live.

## Before you open the form

- [ ] Every team member has checked in on the HackGlobal 2026 event page on Vultr Community
- [ ] Every team member has a Vultr Community account (needed to add them to the project)
- [ ] Your GitHub repo is **public**
- [ ] Your repo has a README with setup steps (use `project-readme-template.md`)
- [ ] No API keys or `.env` file in the repo
- [ ] Your app is deployed on Vultr and the live link works in a private browser window
- [ ] You have architecture screenshots or a diagram showing how your project is built

## Have these ready for the form

| Field | What to write |
| --- | --- |
| Project Name | Your project's name |
| Short Description | What it does, in 1 or 2 sentences |
| Architecture screenshots | Screenshots or a diagram of how the parts connect |
| Industry / Domain | Pick from the dropdown |
| Tags | Select **Hackathons**, plus any others that fit |
| Repository Link | Your public GitHub repo |
| Live Demo URL | Your deployed app on Vultr |
| Tech stack | Languages, frameworks and tools you used |
| Overview description | The problem, the use case and how it works |
| How did you use Vultr? | Which Vultr products you used and for what |
| Team Members | Each teammate's name, email or Vultr Community username |
| Build for an event? | Select **HackGlobal 2026** (without this, your project won't show on the hackathon page) |

## Common mistakes

- Private repo, so judges can't see the code
- Live link that only works on your laptop (localhost)
- Forgetting to select HackGlobal 2026 under "Build for an event?"
- Submitting 5 minutes before the deadline
